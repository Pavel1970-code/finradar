# ADR-011: Канонический локальный набор зарплатных данных

- Статус: принято для MVP
- Дата: 25 июля 2026 года

## Контекст

Одна строка «Зарплата» из платёжного календаря не позволяет проверить налог,
пенсионное участие, долю работодателя и сроки. Прямое связывание Core с номерами
счетов конкретной конфигурации 1С также неприемлемо: планы счетов, регистры и
названия полей различаются.

## Решение

В `FinancialSnapshot` добавляется самостоятельный локальный dataset `payroll`.
Его строки используют канонический контракт `PayrollRecord`. Конкретный
коннектор 1С преобразует поля выбранной конфигурации через
`OneCMappingProfile.payroll_fields`.

Персональные имена и национальные идентификаторы в контракт не входят.
Используется стабильный локальный идентификатор работника. Набор остаётся
внутри Core и не передаётся интернет-модулю.

Нормативные ставки и пороги находятся в отдельном версионированном,
контрольной суммой защищённом снимке. Исключение или льгота не угадывается:
коннектор должен передать соответствующий статус и ссылку на основание.

Платёжный календарь содержит только реальные потоки получателям: чистую
зарплату, налог, пенсионное перечисление и прочие платежи. Валовая зарплата
служит базой и не включается повторно.

## Совместимость

Формат финансового снимка повышен до версии 5. Чтение версий 1–4 сохранено;
для них `payroll_records` считается пустым.

## Последствия

- Можно подключать разные конфигурации 1С без изменения доменной модели.
- Ошибка одной зарплатной строки становится видимым source issue и не скрывает
  остальные строки.
- Прогноз может сопоставить расчётную ведомость с платёжным календарём.
- Реальный транспорт, конкретные регистры 1С и специальные налоговые режимы
  остаются отдельными этапами.
